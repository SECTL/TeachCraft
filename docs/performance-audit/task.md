## 二、任务详情

### T0 · 固化参考机与产物形态

**做什么**
- 在 `spec.md` 写定参考机 A（开发机 24 核 / 16GB）、参考机 B（**≤4 核 / 8GB**）与产物形态
  （发布版 `-sc` 单文件自解压）。
- 规定后续每条性能数字都必须标注机器与产物形态。

**不做什么**
- 不得只测开发机；不得测 `bin/Release` 当作发布产物。

**依赖** 无
**验收** spec.md 含该表；抽 3 条结果行都能看出环境。

### T1 · 基准通道骨架

**做什么**
- 在 `src/TeachCraft.App/App.axaml.cs` 新增走查参数入口（沿用既有 `--slider-bench` 的解析风格），
  形如 `--perf-bench <输出 md 路径>`。
- 新建 `src/TeachCraft.App/Diagnostics/PerfBench.cs`（或等价位置），提供统一的计时与报告写入。
- 报告格式沿用 `SeatGridDiagnostics.FormatReport` 的表格风格（p50 / p95 / 样本数 / 环境信息）。

**不做什么**
- 不引入 BenchmarkDotNet。
- 不改 CI 工作流。
- 不把报告写进仓库（写到 `outputs/`，已 gitignore）。

**依赖** 无
**验收** 跑 `--perf-bench outputs/perf-bench-<日期>.md` 能生成含「环境 / 样本数 / 每项耗时」的 Markdown。

---

### T2 · 合成语料 fixture

**做什么**
- 三档规模：① 3000 人 × 10 科成绩表；② 60 班运动会秩序册；③ 20 班 × 9 学科工作簿。
- 全部**合成**：虚构学校 / 教师 / 学生姓名，符合 AGENTS.md 第十节。
- 放在 `tests/fixtures/perf/`，由生成脚本产出，**生成脚本入库、产物按需生成**（避免大文件入库）。

**不做什么**
- 禁止把任何真实文件内容放进 fixture。
- 禁止使用形似真实姓名的两字组合（旧教训：两字真名被判为扫描伪影）。

**依赖** 无（与 T1 并行）
**验收** 生成脚本可重复执行且产物哈希稳定；`git status` 不出现新增二进制大文件。

---

### T3 · 竞名导入/导出计时埋点

**做什么**
- 在 `OrderBookImporter.Import`、`ScheduleWorkbookImporter.Import`、`MeetExportBuilder.Build`、
  `MeetPdfExporter.BuildPages`、`MeetExportPreviewRenderer.Render` 外层加 `Stopwatch`。
- 结果汇入 T1 的报告通道，不污染用户可见状态栏。

**依赖** T1、T2
**验收** 用 60 班语料跑一次，报告里能看到上面 5 个函数各自的耗时。

### T4 · 时序导入计时埋点

**做什么**
- `MasterScheduleImporter` 的导入总耗时与各子步骤耗时。

**依赖** T1、T2
**验收** 用真实结构工作簿（20 班）跑一次，报告含导入总耗时。

### T5 · 内存基线复测

**做什么**
- 空载稳态工作集、导入后、导出峰值三处。
- **必须在两个硬件档各测一遍**：24 核开发机、低核（≤8 线程）/ 8GB 档。
- 记录方式：`dotnet-counters` 或进程采样，结果写进报告。

**依赖** T1、T2
**验收** 报告里有两档硬件各三项数字；每条都标注机器与产物形态；不得只报开发机。

---

### T6 · 竞名导出预览链路（P0）

**做什么**
- `MeetExportOptionsViewModel.RefreshPreview` 移出 UI 线程：`Task.Run` + `CancellationTokenSource`。
- 加 200–300ms 防抖（照 `ClassBlockViewModel.RefreshPreviewAsync` 的成熟写法）。
- `MeetPdfExporter.BuildPages` 支持「最多分 N 页就停」，预览传 1。
- 预览渲染倍率与导出倍率解耦（预览按显示尺寸，导出保持 1.8 倍不变——导出质量不能降）。

**不做什么**
- 不得改变导出文件的画质、页数、结构。
- 不得让预览与导出走两套分页逻辑导致「预览与成品不一致」。

**依赖** T3（先有基线才能证明变快）
**验收** 60 班语料下，连续切换 10 次设置，UI 线程阻塞峰值 < 200ms；预览内容与导出首页一致。

### T12 · 归位 / 时序补忙碌遮罩（P0）

- 照竞名 `BusyOverlayDelay = 400ms` 的既有实现补同款遮罩，覆盖导入 / 导出 / 生成三条长任务路径。

**不做什么**
- 不得调快 400ms 阈值。
- 不得改变两窗口现有布局与按钮禁用逻辑。

**依赖** 无
**验收** 两窗口导入 / 导出时出现遮罩；400ms 阈值未变；失败路径遮罩可退。

## 四、执行顺序建议

1. **先做 T1 + T2**（半天级），没有基准就没有「变快了」。
2. **T7 / T8 / T11 不依赖任何测量**，可立即并行做掉（三个都是小改动、低风险）。
3. **T3 / T4 / T5** 补齐测量，再进 P0 修复主体。
4. **T6 / T9 / T10** 是本次收益最大的三项。
5. **T12–T14 必须在测量之后**，否则可能优化了不疼的地方。
6. **T15 守卫最后做**，把已修项钉住。
