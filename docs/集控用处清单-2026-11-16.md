## 一、集控实际给知微什么

不是一条文件通道。是三样东西：

| 给的东西 | 具体形态 | 知微怎么用 |
| :--- | :--- | :--- |
| **一棵可对账的结构树** | 地点 → 年级 → 班级（`device/tree`） | 核对班级名；班级名对不上是定向下发失败的头号原因 |
| **一个能收敛的班级状态位** | `desired_state` + `revision`，离线补投 | 让教室机收敛到「该显示哪个班的什么」 |
| **一本不含学生姓名的审计账** | `GET /sites/:id/audit`，含操作者、时间、目标、结果 | 考务可证明「考场上贴的是哪一版」 |

**明确的边界（都核实过）**：

- **没有文件分发**。`api.mjs` 无 multipart、无 bucket、无上传端点；`readBody` 默认 128 KiB。`pushImage` 只是让客户端自己去取一个 URL，Hub 不中转不存储——而且它已从 corkboard 命令表删除。
- **没有调度器**。命令是「现在做」、5 秒超时、不补投、过期即废。没有 cron，没有「定时开机」。
- **`hello.version` 不进设备列表**。`shapeDevice()`（`api.mjs:566`）只回 `protocol`，不回版本号。
- **设备读不到座位**。`GET /classes/:id/seats` 走 `ctxForClass` 要用户令牌；device secret 只能读 tree / assign。
- **桌面端不是天然的设备**。接进来意味着每台教师机持长期密钥 + 25 秒心跳 + 常驻长连接。

## 二、先定三件事，否则后面全是空谈

### 1. 谁接入：教室端，不是工具箱

工具箱装在教师笔记本上、只在检查更新时联网。让它 enroll 成设备，等于每台教师机都有一条常驻连接 + 长期密钥，与「数据不出本机」直接冲突。

**建议分工**：

- **教室大屏 / 讲台机**：跑一个只读展示端，接入集控，负责「按班显示座位表 / 课表」。
- **教师笔记本**：工具箱继续不联网，与教室端只靠导出文件交接。

代价是要维护两个形态。收益是「不联网」这条对绝大多数用户仍然成立。

> 这条与技术路线（一个平台 `teachcraft`、命令按应用前缀分组）并不冲突——**平台只有一个，但只有教室端启用它**。

### 2. 要加一个平台

`PLATFORMS`（`protocol.mjs:380`）只有 `secrandom` / `corkboard`。enroll 之后的 `class.select`、`command`、`settings`、`draw-lock` 一律按它校验。

必须改的地方（漏一处就静默失效）：

| 文件 | 改什么 | 不改会怎样 |
| :--- | :--- | :--- |
| `protocol.mjs` | `PLATFORMS` 加 `teachcraft` | — |
| `protocol.mjs` | `PLATFORM_COMMANDS.teachcraft = [...]` | `command_not_supported` |
| `protocol.mjs` | `PLATFORM_CAPABILITIES.teachcraft`（从命令表派生） | 命令能力自动并集，不派生就要手写 |
| `authz.mjs` | 每条能力加 `CAPABILITY_MIN_ROLE` | **`unknown_capability` 直接拒**；未登记即默认拒绝 |
| `docs/control-center-protocol-v4.md` | §4 能力表 | `check-protocol-doc.mjs` 双向比对会红 |
| `deploy/control-hub/*.mjs` | 逐字节副本 | `check-control-hub-sync.mjs` 会拦 |

**前端不用改**：`/me` 的 `platforms[].capabilities` 与 `platformCommands` 驱动按钮与表单，控制台按能力显隐而不是按平台名写 `if`。

### 3. 姓名上不上云：先定政策

集控的 `seats` 结构**本身就带 `studentName`**（`api.mjs:3224`），但它的审计刻意不记学生姓名。两条口径打架，必须选一条。

**建议定死：云端只放几何与座号，姓名永远留校内。**
教室端按座号 join 本地名单——安全，且不需要改集控的数据结构。

这条不定，后面所有推送设计的字段表都是废稿。

## 三、八条用处

### 1. 考场：一次分配，12 间教室自动上屏（最强）

**谁·何时**：考务，考前 1 天在集控网页。

**做法**：

- 专建「考场」年级 + 12 个班，**不要覆盖真实班级的座位**（覆盖了考后要还原，十个学校九个会漏）。
- 把考场座位（行列 + 座号，姓名留空）写进该班 `seats`。
- 教室端收敛到本班状态后，按座号 join 本地名单，全屏显示，落盘缓存。

**省掉**：12 间教室 ×（拷文件 + 开程序 + 切模式）≈ 20–25 分钟，且要打断 12 次上课。

**三个硬门槛**：

1. 现在设备读不到 seats，必须补一个**设备级** `seats.read`（device secret，只读本班）；
2. Hub 的 `desiredState` 在**内存**里，重启即丢——考场状态必须像 `draw_locked` 那样落库；
3. 知微自己的考场导出还有真 bug（见第五节），不修就先别对外承诺。

### 2. 全校课表：按班定向，不推文件推状态

**做法**：开学前织序排完 60 班，一次灌进集控；之后每次临时调课只重发受影响的班。

**必须新增 class 级期望状态 `timetable`**（学科 × 星期 × 节次 + 作息模板），有 revision、离线补投。不能用命令——5 秒回执、不补投，教室机没开机就漏。

**没有批量端点**，60 班要服务端加一个「导入并按班分发」。

**省掉**：60 班 × 约 40 秒逐班点 ≈ 40 分钟且必错 1–2 个 → 一次导入；调课只发 6 个班，其余 54 个不被打扰。

**注意**：班级名按集控的「年级 + 班名」两段拼，「九（1）班」不能直接拿去比。

### 3. 结构树：当「命名基准」对账，不当「班级清单」录入

**做法**：不让人为了读树去接云。导出后拿树做**对账**——把课表 / 座位 / 报名表里的班级名与 tree 逐个比，对不上就报错。

**收益**：一次全年级对账替代 60 次「这个班怎么推不过去」的排查；顺手省掉「全新制作」里手填的年级名与班数。

**注意**：tree 里**没有一个人名**，也没有班主任、任课教师、课时——它不是名单，替不掉任何一次导入。要省事就让人从网页导出一次 CSV，知微读文件。

### 4. 运维：版本、在线、在跑哪个班

**现状**：设备列表（`device.read` / viewer）已有 online、lastSeenAt、classId、capabilities、machineHost——**但没有版本**。

**最小改动**：服务端在 `updateDeviceReport` 白名单加 `appVersion`，`shapeDevice` 返回它。一处小改，收益最大。

**省掉**：60 台逐台远程桌面查版本约 2 小时 → 一屏；「这台机器知微是不是没起来」从打电话问班主任变成看在线点。

**注意**：匿名接入**不校验平台名**，但后续 `class.select` 会拒——表现成「接进来了却占不了班」。装机时要先试一次占班。

### 5. 审计：谁在什么时候给哪个班推了哪一版座位

**做法**：座位文档算一个 SHA-256 写进推送参数，随 `seat.save` 一起落审计。考后能证明「考场上贴的是哪一版」，而云端一个姓名都没有。

**注意别查错端点**：`/logs` 是命令流水，`/audit` 才是审计。

**已知限制**：两个端点的 limit 是常量（流水 50、审计 100），**协议文档写的 `before` 分页没进代码**。出学期级台账要在服务端补分页或直接查库。保留 30 天，`CONTROL_AUDIT_RETENTION_DAYS=0` 可永久。

### 6. 权限：谁能下发、谁能看

**现状风险（已核实）**：`seats.read` = viewer，而 `seats` 含 `studentName`——**「给他 viewer」等于「给他全校学生座位表」**。

但这在「云端不存姓名」的政策下自然消失（第二节第 3 条）。

**另一个用法**：把「大屏是否显示姓名」做成 `hello.settings.schema` 里的一个 bool，admin 在网页统一下发——学校真正需要的隐私开关，一行 schema 就够，不用给 60 个班各跑一遍。

### 7. 断网：考前 30 分钟看在线，考试当天不依赖网络

**做法**：教室端把最后收敛到的考场状态**落盘**（协议本来就要求 `appliedRevision` 持久化），断网照常显示；同时导出一份「离线考务包」（座位 PNG + 桌贴 PDF + 座位配置 xlsx）放 U 盘。

**价值**：把「断网就考不了」变成「断网只是不能改，而不能改的时候本来也不该改」。

**注意**：集控部署在云端 + 长连接，等于教室机必须能出公网。校园出口一断就是断网场景——别把考试当天的实时性押在网络上，关键动作全部前置到考前。

### 8. 日常座位下发（家长会、公开课、月考后换座）——收益最小，说清楚

**收益**：只比现在多「不打扰其他 59 个班」和「不用老师自己动手」。

但**逐班微信发文件其实只要 10 分钟**。这条只在「教室机常开 + 大屏是 OPS 内置 PC」时才划算，别为它单独投入。

**风险**：会让班主任形成依赖，一旦集控或网络出问题就是「家长会现场打不开」——必须保留「本地文件也能开」的退路。

## 四、明确否定的三条

1. **作息表 → 集控定时指令**
   真实协议**没有调度器**。旧清单里这条作废。按点打铃 / 开关机得服务端新做一套定时机制，与知微无关。

2. **十大工具 → 文件分发**
   真实协议**没有文件分发通道**。`pushImage` 只是让客户端去取 URL，且已从命令表删除。要让教室端拿到 PDF / PPTX，只有「教室端自己从校内共享盘拉」或 U 盘。

3. **成绩条 / 竞名上云**
   绝对不做。集控连审计都刻意不记学生姓名；成绩条是「姓名 + 成绩 + 排名」三件套，竞名是「运动员姓名 + 班级 + 项目」。送进云端库等于同时越过项目红线与集控自己的设计约定。

## 十一、隐私红线（逐项判断）

| 能力 | 结论 | 理由 |
| :--- | :--- | :--- |
| 座位表 / 投影 | ✅ **能做** | 画面在本机渲染，集控只下发「进投影」这条指令。`seatgrid.read` 只回人数与布局，不回姓名与座次 |
| 桌贴 PDF | ⚠️ **不做远程导出** | 每张桌贴是「座号 + 姓名」，生成文件就等于把名单落进集控云端 |
| 成绩条 | ❌ **绝对不做** | 分晓的数据主体就是姓名 + 考号 + 成绩；单帧装不下，必然演变成自建上传通道 |
| 名单 / 花名册 | ❌ **不做**，也不声明 `roster.read` | 不要学 Corkboard 恒回空数组——那样网页仍会显示「读取名单」按钮 |
| 班级名 / 课表 | ✅ **能做** | 班级名在学校内部不是个人可识别信息，且集控本身就存了班级结构。织序冲突摘要只回按 `ConflictKind` 的计数，不回「某教师某节」明细 |
| 竞名 | ❌ **绝对不做** | 运动员姓名 + 班级 + 项目 |

## 十二、技术风险

| 风险 | 说明 | 对策 |
| :--- | :--- | :--- |
| **单文件 / 绿色版** | `ClientWebSocket` 在 BCL 内，不增包体 | 真正的风险是 `PortableUpdater` 自替换：助手进程起来时旧进程已退出，连接自然断；新版本启动后重新 `hello` 并上报 `applied_state_revision`。`Control` 目录在 `%LOCALAPPDATA%` 而非程序目录，`Apply` 只覆盖包内文件 → 凭据不会被冲掉。**别再有人把它挪进程序目录** |
| **还原卡** | `%LOCALAPPDATA%` 被还原 → 每节课重输「地点ID + 配对码」 | 文案写清「装了还原卡请把 `TeachCraft\Control` 加进穿透白名单」 |
| **`Dispatcher.UIThread.Post`** | `StateChanged` 与所有命令处理器都在后台线程 | `seatgrid.exam` 会改 `_assignments` 并 `BuildGrid()`，**必须**整段 Post 到 UI 线程 |
| **断网重连** | 用客户端自带的 1→60s 退避 + ±20% 抖动 | 不要另写。离线 75s 判定、命令直接 409 `offline`、不补投——这正是「指令是现在做」的语义 |
| **被顶（`superseded`）** | 不是错误，本机自动回未选班 | 顶一条红条「本班已被 XX 接管」，**不要**弹重新接入 |
| **吊销（`revoked`）** | 终态 | 清凭证 + 弹「设备已被移除，请重新输入地点ID + 配对码」；收尾清理**不得**把它降级成 `stopped` |
| **`AutoReselect`** | 首期设 `false` | 知微的「占班」和课堂状态不完全一致，自动抢回会和老师操作打架，还会撞 3 秒防抖 |
