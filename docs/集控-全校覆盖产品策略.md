## 〇、一句话战略

对全校老师，TeachCraft + 集控是一间「**插电就正确**」的教室：谁走进去，屏上就是当下该显示的课表、座位与考场；谁被临时指派（监考、代课、值日），屏替他兜底。

覆盖不靠人人装软件、学操作——操作的是四个运营身份（班主任初始化、教务状态通道、考务考场线、电教装机），**受益的是全部**。学生姓名与成绩永远不出本机。

「全校老师不管什么身份都能用上」这句话的成立读法不是「每个老师每天都会打开它」，而是：

> **一年总有几次非它不可（事件驱动），加上每天被动受益（屏自己工作）。**

## 二、两端接入架构（最终推荐）

> 设计师评估了三种形态，综合四位身份提案人的独立收敛，推荐如下。

**同一平台 `teachcraft`，两种身份：**

```
┌─ 教室展示端（设备通道）─────────────────────┐
│ 讲台机 / 大屏内置 PC                          │
│ enroll（地点ID+配对码）→ hello 上报能力      │
│ → class.select 占班 → 收 5 秒指令 + 期望状态 │
│ device/tree 自助选班；断网落盘恢复           │
└──────────────────────────────────────────────┘
                    ▲ 指令经占用表路由（唯一持有者）
┌─ 教师（用户通道）────────────────────────────┐
│ 手机 / 笔记本：不 enroll、不占班、无长连接   │
│ SECTL OAuth（PKCE）→ HTTP API 发指令         │
│ 首期直接用集控网页控制台（补移动端响应式）   │
│ 审计记「哪位老师点的」，不是「哪台机器」     │
└──────────────────────────────────────────────┘
```

**为什么不是另外两种：**

- **形态二（笔记本 enroll 成不占班设备）**：要新写按设备寻址的指令路由（`devicePeer` 现在只用于顶替与吊销，从不用于指令路由）；审计从「哪位老师」退化为「哪台机器」；每台教师机多一条常驻连接 + 长期密钥。
- **形态三（笔记本也占班）**：占用表单持有者——笔记本一占班，教室大屏就从占用表掉出，网页所有指令 409 offline，**展示端被自己的终端打掉**；两机来回 select 还撞 3 秒防抖拉锯。

**同名冲突**：服务端已解——设备名同地点重名自动加后缀「知微 (2)」（`api.mjs:1117-1133`），身份与路由永远用 deviceId。且按推荐形态笔记本根本不 enroll，「同名」前提消失。

**一处对原决策的修正**（采纳数学老师提案）：指令终端首选**手机浏览器**（响应式控制台页），笔记本只是其一——「上一位老师的讲台机不敢碰、自己的电脑不在手边」是流动教师高频尴尬，手机在口袋里。

### 教室机的最终形态：协议 v5「一机一连、多平台」（2026-11-17 定向）

**决策**：采纳形态 B（此前建议 A 先行，用户裁定 B——「一间三行很怪」，且期望设备之下显示各软件的拓扑）。设备是父节点，App 是子节点：网页上一台机器一行，展开是它装的各软件（各自的版本、占的班、在线态）。

v5 改动面（服务端为主）：

- hello v5 声明 `apps[]`（每平台 version + capabilities）；协议 4 兼容——旧客户端的单平台 hello 视为长度 1 的 apps，滚动升级不用发版联动。
- **占用表形状不变**：仍是 `(class_id, platform) → deviceId`，一台设备可同时持有 N 个槽（每平台各占一个班）——指令路由（`hub.mjs:734-742`）、draw-lock 收敛（`applyDrawLock` 逐占用项 bump）、审计**全部零改动**。这是 v5 便宜的核心原因：变的是「谁持有槽」，不是「槽怎么路由」。
- desired_state 键从 deviceId 改为 `(deviceId, platform)`；顶替按槽粒度（`evicted` 带 platform，其他槽不动）；吊销仍整机。
- 设备列表按机器聚合：机器行 → App 子行；**每个 App 独立版本**（各 App 升级节奏不同），机器级版本 = 教室助手版本。
- **教室助手**（管家进程）：唯一持 `device_secret`、一条 WSS、经命名管道多路复用各 App（管道 NDJSON 与 WS 消息同构，协议已预留这个形态）；装机引导接 One-Stop 已规划的下载中心，不自造分发。
- 单 App 的机器可以**不装助手**：App 直连 v5、声明 `platforms:[自身]`——照样一机一行，无迁移损失。

过渡顺序：

1. **teachcraft 平台按 v4 登记**（不等 v5）——考场线不押在协议升级上。
2. **显示层先行**：设备列表按机器指纹（`sha256(guid|host)`，设备文档已有）分组展示——纯 store/前端聚合，零协议改动，「一屋三行」先解一半。
3. **v5 服务端 + 教室助手 + App 换管道传输**，作为一个独立工作流，放在第二个平台真正装进同一台教室机的时机。

安全账（威胁模型补记）：凭据集中到助手 = 一台被攻破则该机全部平台失守（分 App 直连天然隔离一点）；换来的是**「删除机器 = 一次吊销、全部 App 真下线」**，与「删设备必须真下线」的修复正好互相成全。App 级开关保留在各自设置里——「接入集控」关 = 助手 hello 不带这个 App，每 App 的「默认关闭」承诺不受影响。

## 三、覆盖矩阵

| 身份 | 代表用法 | 频率 | 隐私 | 期次 |
|---|---|---|---|---|
| 班主任 | 10 分钟初始化、代课日远程布置、换座（二期） | 初始化一次；代课学期数天 | 名单仅本机 | 首期 |
| 流动科任 | 监考进场屏已就位、值日扫空位、走班屏自报 | 值日/走班每周；监考每学期数次 | 云端仅几何+座号 | 首期 |
| 年轻教师 | 课间网页关投影、巡屏 | 每天低频 | 零 | 首期（搭车） |
| 老教师（零学习线） | 零操作：待机=今日课表、屏自己收 | 每天被动 | 零 | 教室端首期 |
| 教务主任 | 考场制度接管、调课定向重发、通知广播 | 调课每周 3–5 起 | 零 | 首期（考场）+二期 |
| 信息中心 | 装机 SOP、版本巡检、报修分流、审计取证 | 每周 | 零 | 首期 |
| 考务 | 12 间考场一次下发、7:20 核验、一键还原 | 每学期 2 次 | 几何+座号+SHA-256 | 首期 |
| 监考/代课/值日（全员轮值） | 走进教室屏已就位；按屏点人 | 人人轮到 | 低 | 首期（被动受益） |

**审查官 A 对这个主张的裁定**（原话）：按字面不成立——宿管、校医、财务、门卫**结构性排除**，功能教室（实验室/机房/图书馆）在结构树里没有节点、整类挂不进任何班。成立的读法就是第〇节的表述。宿管等身份应继续排除并写明理由，而不是假装覆盖。

## 四、伪需求清单（两审查官 + 提案人自否的三方一致）

| 提案 | 判定 | 一句话 |
|---|---|---|
| 日常换座上屏（首期） | **伪需求** | 归位 PPTX/U 盘只差两分钟；它是唯一把座位数据面日常化搬上云的条目——投入最大、日常依赖最弱 |
| 家长会挂座位图 | **伪需求** | 主持人本来就站在讲台机前，本地 PPTX 完全平价 |
| 运动会教室屏 | **伪需求** | 运动会当天教室是空的；检录处一张纸覆盖八成；运动员姓名是竞名数据主体 |
| 班主任个人便签 | **伪需求** | 增量低于「黑板角写一行」 |
| 成绩条/统计上云 | **永久否决** | 连班平均分也不做（可反推个人）；`roster.read` 有 secrandom 先例（`authz.mjs:70`），「顺手接名单」的诱惑有现实原型，登记平台时就堵死 |
| 桌贴 PDF 远程生成 | **否决** | 每张桌贴是姓名+座号；U 盘物理交接是唯一通道 |
| 通知走命令 | **机制错误** | 命令 5 秒超时不补投，7:20 发、7:40 才开机的教室永久错过——必须走带 `expiresAt` 的期望状态 |

## 五、先做的三件事（两审查官排序一致）

> 审查官 B 的排序被采纳为最终版。真正的瓶颈不是六条场景，而是**三个部署开关**——它们没修，任何场景在第一周热情过后都是黑屏。

### 第一件：知微修考场导出 + 教室端零接触骨架（纯本地，不依赖服务端）

- 修考场导出三缺陷：`ComposeDocument` 取日常布局（`SeatGridViewModel.cs:1744`）、`Columns` 夹到 4（`SeatChartSettings.cs:117`）、`DrawSeat` 不画座号（`SeatChartRenderer.cs:301`）——**考场不接云也已值回票价**。
- 教室端骨架四件：开机自启 + 自动占班（**限开机自动，`AutoReselect=false`**，被顶不抢回）、还原卡凭据自检（写入→重启→校验→绿勾/红叉）、落盘恢复（`appliedRevision` + 最后状态缓存）、本机名单导入向导。
- **验收标准写死**：断电重启 60 秒内，无需任何人工，出现正确画面。

### 第二件：服务端两处小改一次打包

- **安全前提**：`DELETE /devices`（`api.mjs:2708`）与 `rotate-secret` 补 `hub.revokeDevice`（发 `evicted` + 关闭码 4003）；占班与指令复查 secret、比对改 `timingSafeEqual`。审查官原话：删了设备还能占班收指令，「删了的设备必须真下线」——否则台账归零价值。
- **推广执法仪表盘**：`appVersion` 进 `updateDeviceReport` 白名单 + `shapeDevice` 返回（现在不回，`api.mjs:516-531`）；`options.report` 加当前视图枚举（座位/课表/投影/考场/无）。装机向导最后一步自动试占班并回报。
- 审计分页（`limit` 恒 100，store 上限 500 有现成路径）+ `CONTROL_AUDIT_RETENTION_DAYS` 文档化为部署必配项。

### 第三件：考场期望状态端到端闭环（第一个全校场景）

- **class 级**状态落库（type 容器化：`exam/timetable/notice` 共用同一机制），含 revision、离线补投；字段 = 考场号 + 座号 + 行列几何，**无姓名**。
- **实现选型**（信息中心 + 双视角两案合一）：设备**从连接上收敛**（hello 后按库内 class_id 补投），**不开设备级 seats REST**——设备永不碰带 `studentName` 的结构。
- 按年级/考区**批量下发**端点（命令 API 单班，`sendCommand` 单 classId，已核实无批量）一次确认；**批量 on/off 成对**——off 做不到远程批量，on 侧就不敢推。
- 知微侧：考场态渲染收敛、`exam` 处理器 UI 线程投递、`read` 只回标题/人数/布局、考场文档 SHA-256 本地台账、断网兜底的「离线考务包」打包向导（PNG+桌贴 PDF+配置 xlsx 都是现成能力，只差打包壳）。
- 7:20 核验页：设备回报的「44 座」与监考微信回复是两种可信度。

> 排第四（明确不进首期）：timetable/班牌——服务端最重且押「调课必须走织序」的教务录入纪律，先立制度再上屏；且走班场景要求 timetable **按教室编译**而非只按班（审查官 B 抓出的集体盲点：走班屏显示的是「这间教室这一节谁上课」，keyed by 教室）。

## 七、风险与坦诚的边界

- **集控没有文件通道**（`api.mjs` 无 multipart、`readBody` 128 KiB）：名单与课表源文件永远本机/U 盘/校内共享盘导入，集控只同步结构、状态与指令。这句要写进接入页文案，不藏文档。
- **云端自部署无 SLA**：承诺只有「断网 = 不能改」；考试当天实时操作前置到考前 30 分钟验收。
- **注定覆盖不了**：宿管/校医/财务/门卫（结构性排除，写明理由）；后勤与假期值班；运动会现场（人在操场、教室是空的）；教师个人数据场景（成绩条本机已闭环，云端无增量）。
- **功能教室无节点**：实验室/机房/图书馆在「地点→年级→班级」树里挂不进去——要么借「班级」承载，要么推动集控扩一层 venue。这是覆盖缺口里最深的一条。
- **更简单替代永存**：不为增量低于两分钟的场景单独开发。
- **两条运营底线**：删设备必须真下线；**任何需要给王老师开一次培训的功能，不进全校覆盖清单**（零学习判据——四份提案独立收敛到同一条）。
