## 工具说明展开走查（1.16.0）

用 `--shot-metrics` / `--expand-anim` / `--interact` 三条数值通道取证，不依赖肉眼比图：

- **双列宽度**：1200 窗口下卡宽 436.7、两列起点 272 / 715.3；1120 最小宽度下卡宽 396.7、右列起点 675.3，末列右边缘 1072 < 1120，无横向溢出。
- **不再等高**：展开 `image-convert` 后该卡 445.3px，同行 `image-resize` 仍是 82.7px 且顶对齐（`UniformGrid` 时代两张会被拉成等高，未展开的那张下面留 360px 空白）。
- **内容不被裁**：展开卡 `content=362.7 / reveal=362.7 / clipped=no`；四张常备卡展开后 `content` 与 `reveal` 相等（321.3；分晓大卡 350.7–372.7 视宽度而定）。
- **动画确实是渐变的**：`--expand-anim image-compress` 采样 0→362.7 用时约 255ms（进度 0.199 / 0.599 / 0.773 / 0.900 / 0.966 / 1.000），收起同曲线回 0；中途反向时从当前值续接（0.641 → 0.384 → 0.000）而不是跳回端点。
- **交互接线**：`--interact image-compress` 回读「点卡片→True / 点卡内按钮→仍为 True 未被切换 / 点打开→IsToolPanelOpen=True 且 SelectedTool=image-compress / 收起→False」。
- **自动滚动**：展开窗底的 `pdf-split` 后 offset 从 0 变为 1103.3，卡片落在 y=342.7、底部 788 < 804 视口，说明区完整可见。
- **点标题路径**：`--title-click` 从标题 `TextBlock` 发起真实路由 `PointerPressed`，冒泡到卡片根 `Border` 后 `handled=True`、`expanded=True`，再点一次收回；常备卡点大字标题同样生效。
- **键盘路径**：卡片 `Focusable=True`，聚焦后 `Enter` / 空格都能切换且 `handled=True`（注意：不经聚焦直接 `RaiseEvent` 投递按键不会触发，那是测试手法问题，不是产品缺陷）。
- **展开态真的看得见**：`--expand-visual` 回读类名与实测色值——工具卡收起 `bg=#FFFFFF border=#E7E3D8`，展开 `bg=#FFF7F0 border=#D9A58E`、标题色 `#A34A36` 且加下划线；常备卡展开描边变 `#D9A58E`；分晓大卡保持暖底 `#F7F4EB` 同时描边变 `#D9A58E`。
- 这批走查暴露并修掉了四个真实缺陷：
  1. 常备卡 `AppCards` 曾写成 `static` 字段，展开状态跨视图模型共享（测试发现）。
  2. `ExpandReveal.StopTimer` 曾连秒表一起停，重启时只启动计时器，收起动画卡在 1.000（表现为「能展开、收不回去」）。
  3. 工具卡 `Border` 漏了 `Classes.expanded` 绑定，展开态样式是死代码；同时常备卡与分晓大卡把 `Background` / `BorderBrush` 写成局部值，局部值优先级高于样式，使 `.expanded` 描边永远不生效——改为由 `Border.app-card` / `Border.app-card.pinned` 样式提供默认值。
  4. 标题色用祖先选择器 `Border.tool-card.expanded TextBlock.tool-card-title` 设置时被全局 `Style Selector="TextBlock"` 压住，改把 `.expanded` 后缀直接挂在 `TextBlock` 上。
- **减弱动效路径**：`--reduced-motion` 经 `MotionPreference.OverrideForDiagnostics(true)` 注入后，展开 20ms 即 `progress=1.00`、`reveal=content=362.7`，收起 20ms 即 `0.00`，全部直接落位、不留动画残留；恢复探测后回到系统值。生产代码不得调用该注入入口。
- **绑定审计**：`--binding-audit` 遍历实际渲染的 10 张工具卡与 5 张常备卡，比对卡片内 `ToolDescriptionView.DataContext` 是否就是该工具的 `Detail`、并且等于目录里按 key 取到的那一份——15/15 全部 `绑定正确=True`，合计绑定错误 0，各条说明首句互不相同（排除「所有卡共用一个说明对象」）。
- **搜索与展开的交互**：`--search-expand` 展开首件工具后搜「PDF」，该卡被筛掉但 `expanded` 仍为 True（不会被悄悄清掉）；清空搜索后卡片回到列表且 `reveal=1.00`，保持原展开形态。`ToolDescriptionTests` 里有同名测试锁住这条行为。
- **展开着改宽度**：`--expand-resize` 把窗口从 1200 收到 1120，卡宽 436.7 → 396.7、内容高度不变（该区间文字行数没变，属正常）；所有卡片最右缘 1072 < 1120，无横向溢出。另对该说明区直接施加 460→180 的宽度约束，内容高度 362.7 → 362.7 → 362.7 → 422 → 468.7 → 530.7，单调不减，证明宽度变窄时确实重新换行、不会被裁。
- **定时器复用**：`--repeat-toggle 40` 连续 40 轮展开 / 收起后滚动定时器实例数恒为 1（原实现每次展开都 `new DispatcherTimer`，会让 Tick 委托与卡片一起挂在窗口上，反复展开即泄漏且旧计时器会按过期卡片乱滚），最终 `expanded=False`、`progress=0.00`、`reveal=0`。

## 镜像源验证（2026-11-08）

镜像接入的验证分三层，**后两层不可省**——合成测试只能证明「我以为的格式」能被解析。

### 一、合成测试（`SectlMirrorTests` / `MirrorFallbackTests`，23 项）

用 `GuardedHttpHandler` 注入裁剪过的 `/distribution` 响应，锁住：字段映射、只取目标项目、
跳过无 server 源的包、停用版本不出现、正式版用户不被推预览版、回退触发条件、
手动选源不回退、取消不回退、源选择持久化。

### 二、真实响应解析

拉一次真实的 `/distribution`（约 300–360 KB）喂给生产解析代码，核对：
解析出的版本数、每个版本的资产数、**所有下载地址都指向镜像而非 GitHub**、校验清单能被找到。
再按当前版本走一遍 `SelectCandidates` + `UpdateAssetSelector`，确认选出的资产名正确。

### 三、真实下载与校验

从镜像下载一个包（实测用 33 MB 的 `linux-arm64-fdd.zip` 控制耗时），
用镜像托管的 `SHA256SUMS` 校验，确认长度与哈希都对。
另外单独验证过 68 MB 的 `linux-x64-sc.zip` 哈希与 GitHub 发布页清单完全一致。

### 四、多平台资产选择

注入预览身份，覆盖六种组合并核对选出的资产名：
`win-x64-sc` / `win-x64-fdd` / 绿色版 / `win-arm64` / `osx-arm64` / `linux-x64`；
同时确认正式版用户**看不到**预览版。

### 五、发布后核对同步状态

**这一步是本次唯一发现真缺陷的地方，不能省。** 镜像同步分步进行，发布后要核对：

- `projects[].stable_tag` / `latest_version` 是否指向新版本；
- `versions` 表里新版本的 `package_count`；
- **`packages` 表里该 `version_tag` 的实际包数是否与 `package_count` 一致**。

2026-11-08 实测 `v1.18.0` 发布后：`stable_tag` 已是 `v1.18.0`、`package_count: 25`，
但按 `version_tag` 筛 `packages` 是 **0 个**——版本已登记、包还没到。
当时代码把这类「零资产版本」过滤掉了，导致选了镜像的用户被谎报「已是最新」。
合成测试永远测不出这个状态（测试数据里版本和包总是同时存在）。

### 走查通道

```powershell
TeachCraft.exe --check-update mirror --out <绝对路径>.json
```

真实打镜像并按身份选包，结果 JSON 里带 `Source: "sectl"`。
注意 `--out` 只接受绝对路径（防相对路径随调用方漂移）。
本机构建是正式版，看不到预览版，因此这条通道只覆盖「能连上、能解析」；
选包逻辑靠注入预览身份的探针覆盖。
